## 🔥 P0 — Ship this week (bugs breaking user flows)

### 1. Mobile nav is completely broken
- **What**: `.mobile-menu-btn` CSS class is defined but no button element exists in the HTML; on mobile (<768px) `nav-links` disappear entirely, leaving users with no chapter navigation.
- **Where**: `index.html:544–613` (CSS), `index.html:1376–1387` (nav HTML)
- **Why it matters**: Mobile users cannot navigate between chapters at all — they see only the "Share Cards" CTA with no way to find specific content.
- **Effort**: S
- **Suggested fix**:
  - Add `<button class="mobile-menu-btn" aria-label="Open menu">☰</button>` inside `.nav-inner`
  - Create a collapsible panel with the chapter anchor links
  - Wire up a single toggle event listener in the existing script block

### 2. PDF download hardcodes a dead external domain
- **What**: Every PDF generated by the "Download PDF" button includes the URL `openclaw.ai/book`, a domain unrelated to the deployed site.
- **Where**: `index.html:2577`
- **Why it matters**: Every reader who downloads the PDF gets a broken attribution link; damages credibility and makes the PDF untrustworthy.
- **Effort**: S
- **Suggested fix**:
  - Replace the hard-coded string `'openclaw.ai/book'` with `` `${window.location.host}` `` or a single `const CANONICAL_URL` set at the top of the script block

### 3. `copyLink()` silently fails on non-HTTPS or older browsers
- **What**: `navigator.clipboard.writeText()` is called with no `.catch()` handler; if the Clipboard API is unavailable (HTTP deployment, Firefox private mode, iOS WebView), the promise rejects silently and the toast never shows.
- **Where**: `index.html:2752–2755`
- **Why it matters**: The share feature appears broken to some users with no feedback — they click "Share" and nothing happens.
- **Effort**: S
- **Suggested fix**:
  - Add `.catch(() => showToast('Could not copy — please copy the URL from your address bar.'))` to the clipboard call
  - Optionally add the `textarea` + `execCommand` fallback that `cards.html:619–628` already uses (before `execCommand` is removed)

### 4. Audiobook player throws TypeError on unsupported browsers
- **What**: `window.speechSynthesis` is assigned at `index.html:2651` with no feature detection; Firefox on Linux and several mobile browsers lack the API entirely, causing `synth.cancel()` / `synth.speak()` to throw TypeError and crash the script.
- **Where**: `index.html:2651`, `2664–2672`
- **Why it matters**: A JS exception in the audiobook initialization can cascade and break other interactivity on the page (scroll animations, sidebar tracking).
- **Effort**: S
- **Suggested fix**:
  - Guard the top of `toggleAudiobook()` with: `if (!('speechSynthesis' in window)) { showToast('Audio not supported in this browser.'); return; }`
  - Disable the audiobook button UI in browsers where the API is absent

## ⚡ P1 — High ROI (UX friction blocking conversion)

### 5. `scaling.html` and `distribution.html` look like a different site
- **What**: Both pages use `Segoe UI`, a `linear-gradient(135deg, #0f172a …)` background, and blue/emerald card borders (`#3b82f6` / `#10b981`) — completely different from the main ebook's dark green theme.
- **Where**: `scaling.html:7–80`, `distribution.html:7–80`
- **Why it matters**: Readers clicking through experience a jarring visual break that signals "you've left the site" — instant trust drop and higher bounce rate.
- **Effort**: M
- **Suggested fix**:
  - Copy the `:root` token block and `body` base styles from `index.html:10–40` into both pages
  - Replace `Segoe UI` stacks with `'Inter', -apple-system, sans-serif`
  - Replace blue card borders and gradient headings with `var(--accent)` (#22c55e) and the dark background variables

### 6. Sidebar disappears at ≤1280px with no alternative navigation
- **What**: `index.html:1165–1167` hides the chapter sidebar for every viewport narrower than 1280px — tablets, phones, and most laptops that aren't maximized.
- **Where**: `index.html:1165–1167`
- **Why it matters**: Readers on 13-inch laptops or tablets lose chapter-jump navigation for the entire reading session; the only way to navigate is by scrolling from the top.
- **Effort**: M
- **Suggested fix**:
  - Add a sticky "Chapters ▾" dropdown in the top nav that exposes the same anchor list on narrow viewports
  - Or: keep the sidebar but convert it to a collapsible overlay triggered by a hamburger (this also resolves P0 item 1)

### 7. No Open Graph / Twitter Card meta tags on any page
- **What**: None of the four HTML files contain `og:title`, `og:description`, `og:image`, or `twitter:card` meta tags.
- **Where**: `index.html:1–9`, `cards.html:1–10`
- **Why it matters**: Any shared link on Twitter, LinkedIn, Slack, iMessage, etc. renders as a bare URL with no preview card — click-through rates are dramatically lower without a card.
- **Effort**: S
- **Suggested fix**:
  - Add to `<head>` on each page: `og:title`, `og:description`, `og:type = "book"`, `og:url`, `og:image` (a 1200×630 crop of the cover section), `twitter:card = "summary_large_image"`
  - The cover section's visual is already compelling — a screenshot makes a strong share card

### 8. `distribution.html` and `scaling.html` are completely undiscoverable
- **What**: Neither page is linked from the top nav or any in-text link in `index.html`; Vercel rewrites exist but no user can find the URLs unless they already know them.
- **Where**: `index.html:1376–1387` (nav), `vercel.json:6–18` (rewrites with no inbound links)
- **Why it matters**: Content that has been built but is invisible to readers is sunk cost; the distribution and scaling material is potentially the most actionable part of the site.
- **Effort**: S
- **Suggested fix**:
  - Add links to `/distribution` and `/scaling` in the `<footer>` of `index.html` and `cards.html` under a "Go Deeper" section
  - Or add a "Resources" drop-down to the nav

## 🛠 P2 — Code health (tech debt slowing velocity)

### 9. `deploy.sh` would overwrite `server.js` with an outdated version
- **What**: `deploy.sh:27–56` contains a heredoc that recreates `server.js` on the server, but the embedded version is missing the woff/woff2 font MIME types, the PDF MIME type, and the full clean-URL routing logic added in later commits.
- **Where**: `deploy.sh:1–57`
- **Why it matters**: Running `./deploy.sh` silently downgrades the server — PDF downloads and font loading would break.
- **Effort**: S
- **Suggested fix**:
  - Remove the heredoc from `deploy.sh`; Vercel handles deployment; the script is vestigial and should either be deleted or updated to just run `npm start` for local use

### 10. `vercel.json` forces manual rewrite entries for every new page
- **What**: `vercel.json:5` sets `"cleanUrls": false`; three hardcoded rewrites handle `/scaling`, `/distribution`, `/cards`. Any new `.html` file needs a manual entry or it's only accessible at `/file.html`.
- **Where**: `vercel.json:1–20`
- **Why it matters**: New content pages will accidentally expose `.html` extensions or 404 depending on how the link is typed.
- **Effort**: S
- **Suggested fix**:
  - Set `"cleanUrls": true` and remove the three manual rewrites (Vercel's native clean-URL handling covers all `.html` files automatically)

### 11. `index.html` is 2,778 lines of inline HTML + CSS + JS
- **What**: All styles, scripts, and markup live in one file with no separation of concerns.
- **Where**: `index.html:1–2778`
- **Why it matters**: A change to a button style requires scrolling through 1,300 lines of CSS; JS bugs are hard to isolate; the file will hit maintainability limits as it grows.
- **Effort**: L
- **Suggested fix**:
  - Extract the `<style>` block (lines 10–1358) to `style.css`
  - Extract the `<script>` block (lines 2469–2776) to `app.js`
  - This restores exactly the file structure the README already documents but never built

### 12. `cards.html` clipboard fallback uses deprecated `execCommand`
- **What**: `cards.html:620–627` falls back to `document.execCommand('copy')` when the Clipboard API fails; this method is deprecated and removed in Chromium 117+ and Firefox 117+.
- **Where**: `cards.html:620–627`
- **Why it matters**: The fallback intended to rescue old-browser users is itself broken on modern browsers that reject the Clipboard API (e.g., HTTP contexts).
- **Effort**: S
- **Suggested fix**:
  - Replace the `execCommand` fallback with a `prompt('Copy this text:', fullText)` dialog, which works in all browsers and lets users copy manually
  - Or surface a visible text area pre-selected for manual copy

### 13. Card image download has no error guard on `getContext`
- **What**: `cards.html:643` calls `canvas.getContext('2d')`, which can return `null` if canvas is hardware-disabled or the browser is in a resource-constrained state; subsequent `ctx.*` calls throw TypeError with no user feedback.
- **Where**: `cards.html:642–650`
- **Why it matters**: Download card image fails silently — the button appears to do nothing.
- **Effort**: S
- **Suggested fix**:
  - Add `if (!ctx) { showToast('Image generation not supported in this browser.'); return; }` immediately after line 646

### 14. `README.md` describes a non-existent file structure
- **What**: README lists `src/`, `components/`, `chapters/`, `style.css`, `script.js` as existing paths; none exist.
- **Where**: `README.md`
- **Why it matters**: Misleads anyone (including future self) about the architecture; creates confusion when navigating the repo.
- **Effort**: S
- **Suggested fix**:
  - Update the "Project Structure" section to match the actual flat layout with the four HTML files

## 💡 P3 — Nice to have

### 15. Audiobook voice selection is effectively disabled
- **What**: `index.html:2688–2690` calls `synth.getVoices()` synchronously at playback start; voices load async and the list is almost always empty at that moment. The `onvoiceschanged` handler at line 2747–2749 is assigned an empty no-op, so the preferred voice is never applied.
- **Where**: `index.html:2688–2690`, `2747–2749`
- **Why it matters**: The audiobook always uses the system default (often a robotic voice) rather than the natural-sounding voice the code tries to select.
- **Effort**: S
- **Suggested fix**:
  - In `onvoiceschanged`, store `synth.getVoices()` to a module-level `cachedVoices` variable
  - Use `cachedVoices` in `playChapter()` instead of calling `getVoices()` inline

### 16. No `<meta name="description">` on any page
- **What**: All four HTML files are missing `<meta name="description">`.
- **Where**: `index.html:1–9`, `cards.html:1–10`, `scaling.html:1–7`, `distribution.html:1–7`
- **Why it matters**: Search engine results pages show the URL with no description snippet, reducing organic click-through rate.
- **Effort**: S
- **Suggested fix**:
  - Add one `<meta name="description" content="…">` per page (150 chars max)

### 17. Audiobook and PDF buttons have no `aria-label`
- **What**: The audiobook play/pause, next/prev chapter, close, and PDF download buttons are icon-only with no accessible label; screen readers announce them as unnamed buttons.
- **Where**: `index.html:2385–2448`
- **Why it matters**: Screen reader users get no indication of what each button does.
- **Effort**: S
- **Suggested fix**:
  - Add `aria-label="Play audiobook"`, `aria-label="Next chapter"`, `aria-label="Download PDF"` etc. to each `<button>` element
  - Add `aria-hidden="true"` to the SVG icons inside them
